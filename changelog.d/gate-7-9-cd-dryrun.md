### Fixed

- The command walker follows `cd -` to the directory the last `cd`, `pushd` or `popd` of the call left. A `cd -` is left unresolved when the call has not changed directory yet, or when an earlier command may have moved the shell or `OLDPWD` without the walker seeing it: any word containing `OLDPWD`, an `eval`, `source`, `.`, `trap` or `builtin`, a `cd` with options or two operands, a `pushd` without exactly one directory operand, or a `popd` with arguments. In that case ship-gate fails closed and git-guard judges a write where the call starts. Before, `cd -` stayed in place and the wrong clone was judged.
- ship-gate passes a `git push --dry-run` (or `-n`) run outside any clone it can resolve, instead of failing closed with an internal error. A real push there still fails closed with its next step.
