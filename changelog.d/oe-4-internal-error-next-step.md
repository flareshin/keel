### Fixed

- When the ship gate fails closed on a push or merge it cannot judge, the message now ends with a next step: fetch the missing commit, naming it and the repo it comes from (`git -C <clone> fetch origin <sha>`), when a review's base commit is gone from the clone or the refspec source is a full commit id the clone lacks; create the branch or tag first (`git -C <clone> branch <name>`, `git -C <clone> tag <name>`) when the refspec source names no commit; pass the pull request's head commit (`gh pr view <number> --json headRefOid`) when `--match-head-commit` names a commit the clone and its origin lack; spell out a `$variable` the gate reads as written; and run it from inside the target clone when the working directory is not a git repository.
- A command the gate cannot attribute to one repo and branch, run from a directory that is not a git repository, is now denied as unattributable, naming the run-time token, instead of as an internal error.
