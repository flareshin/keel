### Changed

- git-guard replays a commit's same-call staging after one leading `cd <dir> &&`: `cd <dir> && git add <files> && git commit …` is now checked on the index it would commit instead of denied as unreplayable. The `cd` must be the call's first command, ended by `&&`, a bare `cd` with one operand and no assignment, redirect or heredoc; the operand is a literal path, `~` or `~/…` (resolved against the hook's `HOME`), not `-`, `+…`, `~user`, a quoted `~` or a run-time expansion. A relative operand is denied while `CDPATH` is set unless it starts with `./` or `../`, and an operand whose `..` reaches a different directory logically and physically is denied. The index scanned is the one of the repository the `cd` enters, a submodule included. `;`, `||`, a newline, a mid-chain `cd` and any other step before the commit still deny.
- An F-secrets deny whose only bullet is the unreplayable-staging one now puts `Stage with \`git -C <dir> add <files>\`, then commit in a separate call.` before the run-yourself or ask-the-user line.
