### Fixed

- ship-gate denies a `gh api` write to a gated repo unless the endpoint is on its allow-list of discussion writes (issues, issue and pull-request review comments, labels, assignees, reactions; GraphQL `addComment`, `addReaction`, label, assignee and issue mutations), so a contents `PUT` with `branch=main`, `merge-upstream`, `pulls/<n>/update-branch`, a commit status, a workflow dispatch or a GraphQL `createCommitOnBranch` no longer passes. The endpoint is read after stripping the host, a leading slash, the query and fragment, and case; `{owner}/{repo}` and `:owner/:repo` resolve like gh (`GH_REPO`, then the clone's default remote). A write the gate cannot attribute to one repo (`repositories/<id>`, a GraphQL mutation outside the allow-list, a query from a file or `--input`) is denied while any repo is gated, and `xargs` or a wrapper option forwarding a `gh api` write is denied as unattributable. Reads and endpoints outside any repo (`gists`, `user/…`) still pass.
