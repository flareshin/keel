### Fixed

- The ship gate no longer denies `xargs` that appends its input to a git subcommand that only reads (`… | xargs git log --oneline -1`, `xargs -I{} git show {} --stat`) or to a program that cannot push (`xargs grep` with a backtick in its pattern), in a call that spells push or merge elsewhere (`git merge-base`). It still denies `xargs` when the input lands in the program, in the git subcommand (`xargs git`, `xargs -I{} git {} …`), in git's options before the subcommand (`xargs -I{} git -c {} status`), in the arguments of a git subcommand that may push or reroute a push (`git push`, `git config`), or in a shell, and when `xargs` carries an option the gate does not read.
- The ship gate now denies `xargs` whose program is another wrapper that runs its input as a command (`echo git push origin feature | xargs env`, `xargs timeout 60`, `xargs -I{} sudo {} push …`), which it let through before.
- A denied wrapped command now names what the gate cannot read: "`xargs` wraps it: its input becomes the git subcommand", "`xargs` wraps it: the program `$GP` is resolved only at run time", "`sudo` wraps it: it runs `git`".
