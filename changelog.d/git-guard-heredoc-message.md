### Changed
- git-guard's known-value message-form check reads a commit message or PR text given as `"$(cat <<'EOF' … EOF\n)"`, the form Claude Code writes by default, as the heredoc it is: when the `-m` value or the `gh pr` body word is one `$(cat <<'<delimiter>'` whose body runs to a line equal to the delimiter followed by `)`, with no body line holding a `)` or starting with the delimiter, the message counts as read, since under a quoted delimiter the body is literal and the hook already scans it as one of the call's heredocs. With known values loaded, such a commit or PR is no longer denied as a message form the hook does not read. The decision is made on the shell word the parser produced, not on the call text, and the same-call staging replay is unchanged: a commit that stages in its own call with such a message is still denied as unreplayable, and stages in a separate call. The two body conditions follow `/bin/bash` 3.2 (macOS), which ends the substitution at the first unbalanced `)` whatever the heredoc says; a message with parentheses goes through `-F <file>`.
