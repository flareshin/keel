### Fixed

- The command walker follows `cd -` to the directory the call left, but only while every command so far in that shell (and, for `bash -c` or `eval`, in the shell that started it) was a modeled move or a bare assignment. A modeled move is a `cd` with no operand, one non-option operand or `-`, a `pushd` with one non-option operand, or a `popd` with no arguments, each written bare (no wrapper such as `env` or `nohup`, no prefix assignment, not receiving a pipe). After any other command, or a bare assignment to `CDPATH` or `HOME`, `cd -` stays unresolved for the rest of that shell: ship-gate fails closed and git-guard judges a write where the call starts. Before, `cd -` stayed in place and the wrong clone was judged.
- ship-gate passes a `git push --dry-run` (or `-n`) run outside any clone it can resolve, instead of failing closed with an internal error. A real push there still fails closed with its next step.
